# FitCoach AI: 10-minute demo

**Before the demo:** Use a disposable coach account and a separate browser profile for the athlete. Never reset a real roster. Demo athletes have sample data, not athlete logins; use an invite from **App access** on the selected demo athlete’s profile and accept it in the athlete browser. Complete onboarding if prompted. Pick a demo athlete with a WOD scheduled today; if today is a rest day, add a WOD for that athlete on their **Workouts** calendar. Check that AI suggestions are enabled, and keep a prepared pending scaling suggestion and weekly report in **Settings → AI history** as fallbacks if generation is slow. Prepare these after loading the same roster; resetting the demo will remove them.

| Time | On screen | What to say and do |
| --- | --- | --- |
| 0:00–1:00 | **Settings → Demo data → Load demo data** | “Let’s start with a sample gym rather than an empty roster.” Select **Load demo data** on the disposable coach account. If the account you’re presenting from is already prepared, show how the button works on an empty disposable account, then switch to the prepared one. |
| 1:00–2:15 | **Dashboard** | “This is my daily triage: what’s programmed today, what needs my approval, and who needs a follow-up.” Point out the coach-local date, click a WOD, and return. Open a linked attention reason if available; otherwise point out the clear state and explain the signals. Show **This week** and click **Attendance** to see the underlying records. |
| 2:15–3:30 | **Athletes → selected athlete** | Show the athlete’s profile and injury or equipment context, then open **Check-ins** and **Workouts**. Identify the exact WOD you’ll scale. “I can see what’s planned and how this athlete is feeling without leaving their record.” |
| 3:30–5:30 | **Ask AI coach** | On the athlete page, open **Ask AI coach** and ask: “Draft a scaled version of [WOD title] scheduled for [date] for [athlete name]. Keep the intended stimulus and account for their logged limitations.” Read the proposed modifications aloud. Review or edit the changes, then approve the suggestion inline. “This is a draft until I decide what to send.” If generation is slow, open the prepared draft in AI history and review it there. |
| 5:30–7:45 | Athlete **Today → Check-in → Start workout** | Switch to the linked athlete’s browser. Refresh **Today**, show the prescribed and scaled details as available, and submit a check-in. Select **Start workout**, briefly show the timer and movement list, then save a sample result if time allows. “The athlete gets clear instructions; the coach gets feedback.” |
| 7:45–8:45 | **Messages** | In the athlete browser, send a short message about how the scaled WOD felt. In the coach browser, open **Messages**, select the athlete, and reply. Point out that the conversation sits alongside workout and report context. |
| 8:45–10:00 | Athlete profile **Reports** → athlete **Reports** | In the coach browser, open the athlete’s **Reports** tab. Open the prepared report for the last completed week. If there isn’t one, select **Draft weekly report**, then **Edit / full review** on the generated draft. Review the report and select **Approve and share** if it is pending. Switch to the athlete browser and show the report in **Reports**. Close with: “The coach can plan, adapt, follow up, and share progress without switching tools.” |
